# Akzeptanzkriterien / QA für Online-Prototyp

## Funktional

- [ ] Startseite mit Auswahl der Zielgruppe vorhanden.
- [ ] Bogen A, B, C und D sind erreichbar.
- [ ] Jede Submission speichert `module_id` und `module_version`.
- [ ] Pflichtfelder werden validiert.
- [ ] Optionalfelder können leer bleiben.
- [ ] Sprunglogik blendet nicht relevante Fragen aus.
- [ ] Fortschrittsanzeige funktioniert.
- [ ] Abschicken erzeugt Bestätigungsseite.
- [ ] Export nach JSON funktioniert.
- [ ] CSV-Export ist vorbereitet oder dokumentiert.

## Inhaltlich

- [ ] Bogen A ist klar als Patient:innen-Vorab-Anamnese erkennbar.
- [ ] Bogen B ist klar als Rheumanetzwerk-/Ärzteumfrage zur Standardmethode erkennbar.
- [ ] Bogen C ist klar als Patient:innen-Usability-Bogen nach Nutzung erkennbar.
- [ ] Bogen D ist klar als ärztlicher Implementierbarkeitsbogen erkennbar.
- [ ] Bogen B und D werden nicht vermischt.
- [ ] Keine automatische Diagnose wird ausgegeben.

## UI / Layout

- [ ] Mobil und Desktop funktionieren.
- [ ] Fragen sind gut lesbar.
- [ ] Antwortfelder sind groß genug.
- [ ] Keine Elemente ragen über den Seitenrand hinaus.
- [ ] Lange Antwortoptionen umbrechen sauber.
- [ ] Freitexte sind ausreichend groß.

## Datenschutz / Betrieb

- [ ] Demo-Modus ohne produktive Speicherung ist möglich oder dokumentiert.
- [ ] Datenschutz-Hinweis ist sichtbar.
- [ ] Einwilligung ist vor produktiver Speicherung vorgesehen.
- [ ] Personenbezogene Daten sind getrennt oder bewusst vermieden.
